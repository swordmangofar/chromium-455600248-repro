DevTools: "Failed to load response data" for fetch() + Cache-Control: no-store

Repro for crbug.com/455600248.

  1. Open DevTools → Network tab.
  2. Click fetch() + body.getReader().
  3. Select the stock request → Response or Preview tab.

Expected: the JSON body is shown. The page received all of it (see the log below).
Actual: "Failed to load response data: No data found for resource with given identifier". The request still shows status 200, but DevTools got Network.loadingFailed (canceled: true) and no Network.loadingFinished.

Controls (DevTools shows the body):

ConditionBody in DevTools
fetch(), body read via response.body.getReader()missing, needs all three
response has Cache-Control: no-store
response body arrives in more than one piece
response.json() / .text() / XHR / cacheable responseshown

The server sends the same headers as the original report (Spring Boot with Spring Security defaults, which include Cache-Control: no-cache, no-store, max-age=0, must-revalidate). It streams the JSON in 32 pieces 1 ms apart, as Tomcat does when it flushes its buffer. Angular's HttpClient with withFetch() (the default since Angular 22) reads every response this way:

const res = await fetch('/api/b2b/v2/stock', { method: 'POST', body, headers });
const reader = res.body.getReader();
while (!(await reader.read()).done) {}   // the page gets the complete body
